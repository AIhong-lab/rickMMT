# 包租翁 MAX HOUSE｜自動寫手網頁後台

GAS 專案，5 個檔案要分別貼進同一個 Apps Script 專案（不是 Node 專案，沒有 build 流程）。

## 檔案對照

| 這裡的檔案 | 貼到 Apps Script 編輯器的哪裡 |
|---|---|
| `Code.gs` | 蓋掉原本的 `Code.gs`（v3：只把 4 個門檻/寫手常數從 `const` 改成 `let`，新增 `runFour()`，其餘函式一字未動） |
| `Settings.gs` | 新增一個 `.gs` 檔，檔名 `Settings` |
| `WebApp.gs` | 新增一個 `.gs` 檔，檔名 `WebApp` |
| `Index.html` | 新增一個 HTML 檔，檔名必須是 `Index`（doGet 用檔名去找） |
| `appsscript.json` | 專案設定裡的資訊清單（一般要開「顯示資訊清單檔案」才看得到）。如果你的專案已經有這份、且已啟用其他進階服務，用合併的方式改，不要整包蓋過去 |

## 部署步驟

1. 5 個檔案都貼好之後，先點上方「儲存」。
2. 右上角「部署」→「新增部署作業」→ 類型選「網頁應用程式」。
3. 「具有存取權限的使用者」選**「只有我自己」**——這就是唯一的存取控制，不需要另外做登入頁。
4. 「以誰的身分執行」選「我」。
5. 部署後會得到一個網址，手機、電腦開這個網址都能用。
6. **之後只要改了程式碼，一定要「新增部署作業」重新部署成新版本，或用「管理部署作業」更新既有部署，否則網址還是跑舊程式碼。**

## 金鑰設定（沿用原本的方式，沒有變）

「專案設定」→「指令碼屬性」，新增：
- `GEMINI_API_KEY`
- `ANTHROPIC_API_KEY`

網頁介面完全不會顯示、也不會回傳這兩把金鑰。

## 測試方式

1. 部署完成後開網址，先進「系統檢查」頁按「測試金鑰」，兩把都要顯示 ✅ 通過。
2. 進「生成貼文」頁，填一個主題，選支柱，按「開始生成」，正常應該在 60 秒內看到貼文卡片跳出來。
3. 進「品牌設定」頁把「🔥 下限」調低一點（例如改成 3）存起來，回「生成貼文」再跑一次，應該比較容易一次過關——這樣可以確認設定真的有影響 `generatePost()` 的行為。
4. 也可以直接在 Apps Script 編輯器選 `runFour` 或 `run` 執行，去「執行記錄」看 `Logger.log` 的結果，這條路網頁掛掉也能用。

## 交付自檢

- **讀寫方式**：品牌設定、CTA 表、23 人物都是一支 JSON 字串整包讀寫進 `PropertiesService`（key 是 `APP_SETTINGS`），不是逐欄位存取，沒有效能問題。
- **機密處理**：`GEMINI_API_KEY`、`ANTHROPIC_API_KEY` 維持原本存在 `PropertiesService` 指令碼屬性，程式碼裡沒有寫死任何金鑰，網頁前端也拿不到這兩個值。
- **執行時間**：前端一次只呼叫一篇 `generatePostForWeb`，單篇最多重寫 `MAX_ROUNDS` 輪（預設 3 輪），每輪一次 Claude + 一次 Gemini 呼叫，正常應在 1 分鐘內完成，遠低於 GAS 單次執行 6 分鐘的上限；四篇是前端依序送出、不是平行送出，所以不會疊加成同一次執行超時。
